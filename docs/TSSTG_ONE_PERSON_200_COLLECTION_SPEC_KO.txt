한 사람 TSSTG 이진 낙상 데이터 200개 수집 간소화 명세

목적
  - YOLO는 파인튜닝하지 않고 배포 NCNN YOLO의 pose 결과만 저장한다.
  - 한 사람으로 빠르게 binary TSSTG prototype을 train/test한다.
  - 이 결과는 동일인·동일 방 개인화 성능이며 타인 일반화 성능으로 해석하지 않는다.

총 200개 이벤트
  FALL 100개
    F01 앞으로 넘어지기                 20
    F02 뒤로 넘어지기                   20
    F03 좌/우 옆으로 넘어지기           20
    F04 걷기/방향전환 중 넘어지기       20
    F05 천천히 주저앉기/벽 타고 내려가기 20

  NON_FALL 100개
    N01 걷기·멈춤·방향전환                         20
    N02 의자 앉기 또는 침대에 정상적으로 눕기      20
    N03 물건 줍기·쪼그리기·무릎 꿇기               20
    N04 빠르게 앉기/눕기 또는 비틀거린 뒤 회복      20
    N05 바닥에 앉기·눕기·뒤척이기·일어나기          20

각 20회 안에서는 위치와 조건을 바꾼다.
  - 중앙 8, 좌측 4, 우측 4, 가까운 곳 2, 먼 곳 2 정도
  - 정면/후면/좌측면/우측면을 최소 4회씩 포함
  - 일반 조명 14, 어두운 조명 6
  - 옷은 최소 2벌
  - F03은 좌우 각각 10회
  - 작업자 혼동을 막기 위해 한 장소에서 한 subtype의 10회를 끝낸 뒤 다음 subtype으로 이동한다.
  - 반복 1~14는 train, 15~16은 validation, 17~20은 test로 collection_plan.json에 고정한다.
  - 위치(position), 방향(view), 조명(lighting), 옷(outfit), F03 좌우(fall_side)를 event manifest에 저장한다.
  - location_1: F01, N01, F02, N02, F03, N03, F04, N04, F05, N05를 각각 1~10회
  - location_2: 동일한 순서로 각 subtype을 각각 11~20회
  - 각 장소는 subtype별 10개, FALL 50개와 NON_FALL 50개로 동일하게 구성한다.

UI 동작
  1. 라이브 화면에서 다음 동작을 확인한다.
  2. 좌클릭하면 2초 countdown이 시작된다.
  3. RECORD 표시 후 약 4초 동안 30 FPS RGB를 RAM에만 임시 보관한다.
  4. 균일한 25 Hz 시간축에 가장 가까운 고유 RGB 100장을 선택해 pose를 추출한다.
     100개 고유 프레임 또는 최대 30 ms 시간 오차를 만족하지 못하면 자동 폐기하고 재촬영한다.
  5. 수집 후 RGB+관절 화면과 skeleton-only 화면을 좌우로 25 FPS 반복 재생한다.
  6. 좌클릭: 승인하고 다음 샘플로 이동한다.
  7. 우클릭: 방금 pose와 영상을 폐기하고 같은 샘플을 다시 수집한다.
  8. Q: 안전하게 종료한다. 다시 실행하면 승인 완료 다음 번호부터 이어진다.

저장
  - 승인된 pose: collected_pose_data/S001/samples/S001_E###.npz
  - event manifest: collected_pose_data/S001/events.jsonl
  - 계획: collected_pose_data/S001/collection_plan.json
  - 최근 검수 영상 하나만: collected_pose_data/S001/latest_review.mp4
  - 최근 원본 RGB 버퍼 하나만: collected_pose_data/S001/latest_buffer.mp4
  - 다음 승인 시 latest_review.mp4는 덮어쓴다.
  - latest_buffer.mp4는 관절/문자 오버레이가 없는 최근 정상 4초 버퍼이며 다음 촬영 때 덮어쓴다.
  - 과거 RGB 영상은 보존하지 않는다.
  - NPZ에는 17관절 xy/conf, bbox, timestamp, valid mask를 저장한다.
  - NPZ의 pose_count는 항상 100이며 source/target timestamp와 RealSense frame number도 저장한다.
  - bbox는 수집 품질 확인용으로만 보존하며 TSSTG 입력과 window 자동 선택에는 사용하지 않는다.

  출력
    - train.npz: 140개, features (140, 30, 14, 3), labels (140,)
    - validation.npz: 20개, features (20, 30, 14, 3), labels (20,)
    - test.npz: 40개, features (40, 30, 14, 3), labels (40,)
    - windows.csv: event별 split, 선택 window, fall_start/impact 자동 추정값 및 조건 메타데이터
    - dataset_summary.json: 클래스와 shape 요약

Train/Test 분할
  - 한 사람 데이터이므로 random window split은 금지한다.
  - 먼저 수집 순서와 조건을 고려해 event 단위로 80/20을 고정한다.
  - 권장 train 140개: 각 subtype 1~14회(70 FALL + 70 NON_FALL)
  - validation 20개: 각 subtype 15~16회(10 FALL + 10 NON_FALL)
  - test 40개: 각 subtype 17~20회(20 FALL + 20 NON_FALL)
  - 겹치는 30-frame window는 반드시 원본 event와 같은 split에 둔다.
  - subtype마다 반복 15~20은 가능하면 반복 1~14와 다른 날 또는 세션에 촬영한다.
  - test 40개는 다른 옷과 조명을 사용하고 최종 한 번만 평가한다.

라벨
  - 수집기 event label은 FALL 또는 NON_FALL이다.
  - 4초 stream 전체를 하나의 30-frame sample로 즉시 축약하지 않는다.
  - Colab에서 30 frame(1.2초) window를 만든다.
  - FALL 촬영은 RECORD 직후 0.5~1.0초 안에 하강을 시작하는 것을 권장한다.
  - fall motion이 포함된 window만 FALL로 사용하고, 준비/회복 구간은 제외한다.
  - NON_FALL은 해당 동작 구간의 window를 사용한다.
  - 첫 버전은 수집 event 전체가 binary label이라는 약식 라벨을 사용할 수 있지만,
    FALL 4초 전 구간을 전부 FALL로 지정하면 서 있는 준비 자세까지 FALL로 학습되는 오류가
    생긴다. Colab builder가 motion 크기 또는 운영자 입력 시점을 이용해 실제 하강 구간을
    선택해야 한다.

fall_start와 impact의 의미
  - 두 값은 모델이 출력할 별도 class가 아니라 FALL window를 만드는 정답 timestamp이다.
  - fall_start: 통제되지 않은 하강이 시작된 시점
  - impact: 몸이 바닥/매트에 처음 접촉한 시점
  - 학습 시 두 시점이 포함된 30-frame window를 FALL로 지정한다.
  - 모델의 최종 출력은 계속 NON_FALL과 FALL 두 개뿐이다.
  - 실시간 모델은 fall_start/impact 시각을 직접 회귀하거나 각각 예측하지 않는다.

안전
  - 두꺼운 매트와 보조자를 반드시 사용한다.
  - 후방 낙상에서 머리를 바닥에 닿게 하지 않는다.
  - 피로하면 즉시 중단하고 여러 세션으로 나눈다.
  - 실제 딱딱한 바닥 낙상을 수행하지 않는다.

한계
  - 동일인 test는 코드와 개인화 가능성 확인용이다.
  - 다른 사람, 체형, 실제 고령자, 다른 방에서의 성능을 증명하지 않는다.
  - YOLO가 잘못 만든 pose만 저장하므로 나중에 YOLO 모델을 바꾸면 재추출할 수 없다.
  - latest_review.mp4 한 개만 남으므로 각 샘플을 승인하기 전에 반드시 반복 재생을 확인한다.
